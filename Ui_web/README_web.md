# README — หน้าเว็บระบบยืม-คืนอุปกรณ์ (RFID-based Item Borrowing System)

เอกสารนี้สรุป requirement ทั้งหมดที่คุยกันไว้ เพื่อ align ก่อนเริ่มเขียนโค้ดจริง

---

## 1. บทบาทผู้ใช้งาน (Roles)

| Role | เข้าสู่ระบบด้วย | ทำอะไรได้ |
|---|---|---|
| **แอดมิน** | Username/Password แบบ hardcode | จัดการห้อง, จัดการแท็ก, จัดการของในห้อง, ดู log ทั้งหมด |
| **ครู** | แตะแท็กประจำตัว (ไม่มีฟอร์ม login) | ดูห้อง/กุญแจที่ตัวเองดูแล, ดู log การยืม-คืนของแท็กตัวเอง |
| **นักเรียน (ผู้ใช้)** | ชื่อ + ห้อง + เลขที่ + รหัสประจำตัวนักเรียน | ยืม/คืนของ, ดูประวัติการยืมของตัวเอง |

**กฎรหัสนักเรียน:** ไม่ตรวจสอบกับฐานข้อมูลจริงภายนอก ตรวจแค่ **ต้องขึ้นต้นด้วย `693190`** และมีความยาวรวมตามตัวอย่าง เช่น `69319011766` (ระบบไม่เช็คว่ามีตัวตนจริงหรือไม่ แค่ format ผ่านก็เข้าได้)

---

## 2. หน้าแดชบอร์ดหลัก (สาธารณะ/ล็อกอินแล้วเห็น)

- แสดง **จำนวนห้องทั้งหมดที่ระบบรองรับ**
- แสดงแถบห้อง (Room Card) **1 แถบต่อ 1 ห้อง** โดยดีฟอลต์แสดง**เพียงห้องเดียว** พร้อมปุ่ม **"ดูเพิ่มเติม"** กดแล้ว expand ลงมาเห็นทุกห้องในระบบ
- แต่ละแถบห้องแสดง:
  - เลขห้อง
  - เลข ID ของแท็กกุญแจประจำห้องนั้น (แสดงใต้การ์ด)
  - สถานะ (ว่าง / ถูกยืมอยู่)

---

## 3. การเพิ่มห้อง / ลงทะเบียนแท็กใหม่ (เฉพาะแอดมิน)

Flow การเพิ่มห้องใหม่:
1. แอดมิน login เข้าระบบ
2. กดปุ่ม **"เพิ่มห้อง"** ในหน้าเว็บ → ระบบเข้าสู่โหมด "รอรับแท็ก"
3. นำแท็กจริงไปแตะที่เครื่องอ่าน 1 ครั้ง → ระบบอ่านเลข UID มาโชว์
4. แอดมินกรอกข้อมูลเพิ่มเติม (เลขห้อง, รายละเอียด) แล้วกดยืนยันผูกแท็กนี้เข้ากับห้องนั้น

**หลักการเดียวกันนี้ใช้กับการลงทะเบียนแท็กครูด้วย** — ต่างกันแค่เลือกว่าจะผูกเป็น "แท็กครู" หรือ "แท็กห้อง"

---

## 4. หน้าโปรไฟล์ครู

แสดงข้อมูล:
- ชื่อครู
- วันที่บันทึกแท็ก (วันที่ลงทะเบียนแท็กเข้าระบบ)
- Log การยืม-คืนของทุกแท็ก (ห้อง/กุญแจ) ที่ครูคนนี้ดูแล — **ครู 1 คนดูแลได้หลายแท็ก**

**กรณีป้องกันการใช้แท็กผิดคน:**
ถ้าครู A แตะแท็กตัวเอง แล้วมีคนพยายามเอาแท็กห้องที่ครู A **ไม่ได้ดูแล** มาแตะต่อ → ระบบต้องปฏิเสธ และ**บันทึก log ความพยายามที่ผิดพลาดนี้ไว้ด้วย** (เพื่อ audit)

---

## 5. หน้าจัดการของในห้อง (เฉพาะแอดมิน)

แอดมินต้องมานั่งกรอกล่วงหน้าว่าในแต่ละห้องมีอะไรให้ยืมบ้าง แต่ละรายการมี:
- ชื่ออุปกรณ์
- จำนวนที่มี
- กำหนดวันที่ต้องคืนภายใน (default ต่อรายการ)
- รูปภาพจริงของอุปกรณ์ (สภาพตอนก่อนให้ยืม)

---

## 6. Flow การยืม (Borrow)

1. **ต้องแตะแท็กครู 1 ครั้งก่อนเสมอ** (ไม่มีข้อยกเว้น — แตะแท็กห้องเดี่ยวๆ ไม่ได้เด็ดขาด)
2. ระบบตรวจว่าแท็กครูนี้ valid และพร้อมรับแท็กห้องต่อ (ภายในเวลาที่กำหนด เช่น 15 วินาที)
3. แตะแท็กห้อง/กุญแจ → ระบบเช็คว่าครูคนนี้มีสิทธิ์ดูแลห้องนี้จริงไหม
4. ผู้ใช้ (นักเรียน) ที่ login ค้างอยู่ในระบบ เลือกรายการของที่จะยืมจากลิสต์ของห้องนั้น (จำนวน, ชนิด)
5. ระบบบันทึก transaction: ชื่อครู, เลขห้อง, ชื่อนักเรียน, รายการที่ยืม, เวลาที่เบิก, กำหนดคืน

---

## 7. Flow การคืน (Return)

1. แตะแท็กครู 1 ครั้งก่อนเสมอ (เหมือน flow ยืม)
2. แตะแท็กห้อง/กุญแจ
3. ผู้ใช้ **อัปโหลดรูปอุปกรณ์ที่นำมาคืน**
4. กดยืนยัน → ระบบบันทึกเวลาที่คืน พร้อมรูปภาพ ปิด transaction

---

## 8. หน้าโปรไฟล์นักเรียน

แสดง:
- ชื่อ, ห้อง, เลขที่, รหัสประจำตัว
- วันที่สร้างบัญชี
- วันที่เข้าสู่ระบบล่าสุด
- ประวัติการยืมทั้งหมด: ยืมจากห้องไหน, กับครูคนไหน, ยืมอะไรไปบ้าง, คืนแล้วหรือยัง, คืนตรงเวลาไหม

---

## 9. โครงสร้างข้อมูลเบื้องต้น (Data Model แบบร่าง)

```
admins
├─ id, username, password (hardcoded)

teacher_tags
├─ id, card_uid, teacher_name, registered_at

room_tags
├─ id, card_uid, room_number, teacher_id (FK -> teacher_tags, ผู้ดูแล)
   -- 1 teacher ดูแลได้หลาย room_tags (1-to-many)

room_items
├─ id, room_id (FK), item_name, quantity, return_due_days, image_path

students
├─ id, name, room, seat_no, student_code, created_at, last_login_at

transactions
├─ id
├─ teacher_tag_id (FK)
├─ room_tag_id (FK)
├─ student_id (FK)
├─ item_id (FK -> room_items)
├─ quantity_borrowed
├─ borrowed_at
├─ due_date
├─ returned_at (null = ยังไม่คืน)
├─ return_image_path (null จนกว่าจะคืน)
├─ status ('borrowed' / 'returned' / 'overdue')

access_violation_logs   -- เก็บ log กรณีแท็กห้องถูกใช้กับครูที่ไม่มีสิทธิ์
├─ id, teacher_tag_id, room_tag_id, attempted_at, result ('denied')
```

## 10. ประเด็นที่ต้องตัดสินใจเพิ่มก่อนเริ่มเขียนโค้ด

- [ ] เวลาที่ยอมให้แตะแท็กครู แล้วรอแตะแท็กห้องต่อ ควรตั้งกี่วินาที (เช่น 15 วิ)?
- [ ] ถ้าผู้ใช้ (นักเรียน) ยังไม่ได้ login ตอนแตะแท็ก จะให้ระบบทำยังไง (บังคับ login ก่อนแตะ หรือ login ทีหลังตอนเลือกของ)?
- [ ] รูปภาพอุปกรณ์ (ตอนเพิ่มของ และตอนคืน) จะเก็บเป็นไฟล์ในเซิร์ฟเวอร์ หรือฐานข้อมูล (แนะนำเก็บเป็นไฟล์ แล้วเก็บแค่ path ใน DB)
- [ ] Overdue (เกินกำหนดคืน) ต้องการแจ้งเตือนแอดมิน/ครูไหม หรือแค่ขึ้นสถานะในตารางพอ

## 11. หน้าเว็บที่ต้องมี (สรุปเป็น Page List)

1. `index` — แดชบอร์ดหลัก (แสดงห้อง + ปุ่มดูเพิ่มเติม)
2. `login` — เลือกโหมด: แอดมิน / นักเรียน
3. `admin/dashboard` — ภาพรวมแอดมิน
4. `admin/add-room` — โหมดรอรับแท็กห้องใหม่
5. `admin/add-teacher-tag` — โหมดรอรับแท็กครูใหม่
6. `admin/manage-items` — จัดการของในแต่ละห้อง (เพิ่ม/แก้ไข พร้อมรูป)
7. `admin/logs` — log ทั้งหมด รวมถึง access violation
8. `teacher/profile/:id` — โปรไฟล์ครู + log แท็กที่ดูแล
9. `student/profile/:id` — โปรไฟล์นักเรียน + ประวัติยืม-คืน
10. `borrow-flow` — หน้าที่โต้ตอบกับการแตะแท็ก 2 ครั้ง + เลือกของยืม
11. `return-flow` — หน้าที่โต้ตอบกับการแตะแท็ก + อัปโหลดรูปคืน
